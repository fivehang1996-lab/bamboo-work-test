# 《绿梦》流失分析报告 — 可视化建议与可行性评估

> 报告当前形态：纯文本 Word 文档，含 4 张图片（表格/图表，无法提取）。建议目标：提升汇报效果和数据可读性。

---

## 一、当前问题诊断

| 问题 | 影响 |
|------|------|
| 全文纯文字，无图表 | 读起来累，关键数据淹没在段落里 |
| 多处"A高于B""A低于B"对比 | 靠文字对比效率低，一张柱状图秒懂 |
| 5类玩家画像全文字描述 | 无法直观感受群体间差异 |
| 流失原因分散在三处 | 缺少一条从"谁流失"到"为什么"的因果链 |
| 表格数据全在图片里 | 无法直接引用、无法转成可交互图表 |

---

## 二、可视化方案与可行性

### 方案1：做成网页视频报告（推荐）

> 即我们已有的工作流：口播稿 + 动态画面 + 自动播放。最适合向业务方汇报。

**怎么用在这里**：
- 每个分析结论一个画面，图表驱动讲解
- 关键数字放大、动画入画，视觉冲击力强

| 评估 | |
|------|------|
| 可行性 | ★★★★★ 已有成熟模板，0 技术门槛 |
| 效果 | 汇报场景最佳，自动播放解放讲解人 |
| 工作量 | 1-2 小时生成完整视频报告 |
| 限制 | 表格数据要从图片手动提取 |

---

### 方案2：流失漏斗图

**画面**：三层漏斗——总玩家 → 次日留存 → 三日留存 → 活跃≥6天

| 评估 | |
|------|------|
| 可行性 | ★★★★★ HTML/CSS 绘制，或 ECharts 一行配置 |
| 效果 | 一图讲清流失规模 |
| 工作量 | 10 分钟 |
| 限制 | 需要具体流失率数字（目前报告中未提供百分比，需补充） |

---

### 方案3：多维度留存率对比柱状图

**画面**：同一维度下不同分组的留存率并列对比。例如：
- 性别：男 vs 女 的次日留存/三日留存/全留存
- 年龄：6 段 × 3 类留存
- 城市线级、设备平台、游戏经验等同样

| 评估 | |
|------|------|
| 可行性 | ★★★★★ ECharts 或 Chart.js，数据准备好即出图 |
| 效果 | "谁更容易流失"一目了然 |
| 工作量 | 每维度 15 分钟，约 6 个维度 |
| 限制 | **核心瓶颈——报告中未提供具体留存率数字**，只有文字描述"更高/更低"。需要从原始数据或图表图片中提取 |

---

### 方案4：五类玩家雷达图

**画面**：剧情党/操作党/解谜党/厨力党/强度党，用雷达图展示多维度差异（年龄/城市/设备/游戏经验/留存）

| 评估 | |
|------|------|
| 可行性 | ★★★★☆ ECharts 雷达图 |
| 效果 | 玩家聚类最直观的表达方式 |
| 工作量 | 20 分钟 |
| 限制 | 同样需要定量数据；且雷达图轴过多会拥挤，建议每个集群挑 5-6 个核心维度 |

---

### 方案5：流失原因横向对比图

**画面**：三组横向对比——留存/次日流失/三日流失，在各维度上的评分/百分比。用分组柱状图或热力图。

维度包括：好评点（美术/玩法）、差评点（按键/卡顿/战斗/美术）、上手难度、继续游玩意愿

| 评估 | |
|------|------|
| 可行性 | ★★★★★ 分组柱状图 |
| 效果 | 直接展示"次流差在哪、三日流失差在哪" |
| 工作量 | 20 分钟 |
| 限制 | 报告中有一些百分比线索可提取，但精确数字仍需原始数据 |

---

### 方案6：流失因果链路图

**画面**：从左到右的因果链——谁在流失 → 什么时候流失 → 为什么流失 → 怎么优化

用流程图/桑基图表达不同玩家群体流向不同流失原因

| 评估 | |
|------|------|
| 可行性 | ★★★☆☆ 需手动设计布局，或用 Mermaid/ECharts Sankey |
| 效果 | 汇报收尾的"一张图总结"，含金量高 |
| 工作量 | 40 分钟，需梳理因果逻辑 |
| 限制 | 桑基图需要定义节点和流向权重，数据准备稍复杂 |

---

### 方案7：可交互数据看板

**画面**：一个 HTML 页面，包含多个可交互图表（筛选人群、切换维度、hover 看详情）

| 评估 | |
|------|------|
| 可行性 | ★★★★☆ ECharts + HTML，技术上没问题 |
| 效果 | 业务方自己探索数据，比静态报告好用 |
| 工作量 | 3-4 小时 |
| 限制 | 需要完整数据集（目前缺失）。更适合"有了数据之后"的深度交付 |

---

### 方案8：Word/PPT 内嵌图表

**画面**：在 Word 或 PPT 中手工插入 chart

| 评估 | |
|------|------|
| 可行性 | ★★★★★ 直接操作 |
| 效果 | 中规中矩，不如网页方案出彩 |
| 工作量 | 1-2 小时 |
| 限制 | 静态，不能自动播放 |

---

## 三、核心瓶颈

**无论哪种方案，最大的瓶颈都是：报告中大部分数据是定性描述（"更高/更低/更突出"），缺少具体的定量数字。**

| 能直接用 | 不能用 |
|-----------|--------|
| 玩家分层定义（留存/次流/三日流） | 各组具体留存率 |
| 5 类玩家画像定性特征 | 各聚类占比 |
| 差评/好评的排序和方向 | 好评率/差评率百分比 |
| 4 张表格图片 | 图片中的数据未提取 |

## 五、建议

**最快见效路径**：先做方案1（网页视频报告），把现有文字内容直接转成可播放的汇报视频。图表部分先用"拟图表"——就是 CSS 画的简易柱状图/对比框，把方向和趋势表达出来，不追求精确到小数点。如果后续拿到定量数据，再补实锤图表。
